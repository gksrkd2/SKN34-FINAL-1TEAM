# RAG 기반 예상 공정표 에이전트 성능지표

## 기준

발표·포트폴리오 성능 평가는 아래 기준을 사용한다. 이번 1차 개발의 실제 측정값을 최초 Baseline으로 저장하고 이후 개선 버전을 같은 데이터와 조건으로 비교한다. 기존 저장소 코드는 비교 대상이 아니다.

현재 실제 LLM·RAG·전체 사용자 흐름 측정은 수행하지 않았다. 아래 미측정 항목을 기존 함수·Stub 검사 결과로 대체하지 않는다.

## 측정 항목

| 구분 | 지표 | 측정·판정 기준 | 1차 결과 |
|---|---|---|---|
| 공정표 결과 | 전체 작업 성공률 | 올바른 공정표와 질문에 맞는 근거 있는 설명까지 완성한 정상 사례 / 정상 사례 | 미측정 |
| 공정표 결과 | 공정표 정확도 | 작업일·시작/종료일·공정 순서·휴일·대기일·사용자 조건이 별도 정답과 모두 일치한 정상 사례 / 정상 사례 | 미측정 |
| LLM 답변 | 질문별 정답률 | 사전에 정한 질문별 정답·필수 내용을 충족한 정상 요청 / 정상 요청 | 미측정 |
| LLM 답변 | 근거 일치율 | 검색 문서·DB·계산 결과로 뒷받침되는 사실 주장 / 평가 답변의 전체 사실 주장 | 미측정 |
| LLM 답변 | 환각률 ↓ | 입력·검색 문서·DB·계산 결과에 없는 사실을 포함한 응답 / 전체 평가 요청 | 미측정 |
| RAG 검색 | Precision@K | 상위 K개 중 정답 관련 청크 수 / K의 질의별 평균. K개 미만 반환도 분모는 K | 미측정 |
| RAG 검색 | Recall@K | 상위 K개 정답 관련 청크 수 / 해당 질의의 전체 정답 관련 청크 수의 질의별 평균 | 미측정 |
| RAG 검색 | MRR | 첫 정답 관련 청크 순위의 역수 평균. 미검색은 0. 전체 반환 순위에서 평가하며 검색 상한도 기록 | 미측정 |
| RAG 검색 | nDCG@K | 관련도 등급에 따른 DCG@K / 이상적 순위의 DCG@K의 질의별 평균 | 미측정 |
| 응답 속도 | P50·P95·P99 | 입력 요청부터 공정표와 실제 LLM 설명 완료까지의 ms. 최근접 순위 방식 백분위 | 미측정 |
| 비용 | 요청당 토큰·비용 | 공급자 실제 입력/출력 usage와 측정 시점 모델 단가로 계산한 요청당 평균·전체 합계 | 미측정 |

생성 실패도 공정표 정확도와 전체 작업 성공률의 분모에서 빼지 않는다. 빈 답변·실패·타임아웃은 질문별 정답률에서 실패다. 근거 일치율은 평가 가능한 주장 수를 함께 보고하고 주장이 없으면 100%로 표시하지 않는다. 환각률에는 무응답·실패 건수를 함께 표시한다. 모델 원출력과 검증 후 전달한 결과는 구분한다.

## 평가 데이터 준비

- 공정표: 최소 15개 사례, dev 10개·held-out 5개. 목공·도배·복합, 정상·입력 부족·단위 오류·휴일·경계 사례를 포함한다. 실제 사용자 제공 사례와 평가자가 만든 대표 입력을 구분한다.
- 계산 정답: 사용자 입력 물량·주 직종 인원과 실제 DB 품·할증을 업로드 계산식으로 별도 검산한다. 운영 계산 함수의 결과를 그대로 정답으로 쓰지 않는다.
- RAG: 전처리 청크 본문·고유 ID·출처를 바탕으로 질문 30개를 준비한다. 질문 ID, 질문, 정답 답변, 전체 관련 청크 ID 목록, 관련도 등급, 선정 근거, dev/held-out 구분을 기록한다. dev 20개·held-out 10개로 고정한다.
- GPT가 만든 라벨은 후보이며 원본 청크와 대조해 검토한 후 확정한다. 알려진 관련 청크만 일부 라벨링하면 Recall과 nDCG 해석에 한계가 있으므로 라벨 검토 범위를 기록한다.
- 관련도는 0(무관)·1(일부 근거)·2(핵심 근거)로 고정하고 1 이상을 관련 청크로 센다. nDCG의 이득은 2^등급−1, 할인은 log2(순위+1)로 계산한다.
- K=5를 최초 기준으로 사용한다. 답이 없는 질문도 포함하되 관련 문서가 없는 질의는 Recall·MRR·nDCG 평균에서 제외하고 별도 개수와 안전한 응답 결과를 보고한다. Precision@5도 검색 가능한 질의 집단 기준으로 보고한다.
- 정답과 라벨은 평가 출력 확인 전에 확정한다. 사례 수·중복·정상/예외 분포와 반복 횟수를 기록한다. 검증셋을 보고 튜닝했다면 별도 표시한다.

## 실행·비교 조건

1. 1차 코드·프롬프트 해시, 모델명·파라미터, 산식·DB 자료·청크·임베딩·검색 설정 버전, 실행 환경과 측정 시각을 기록한다. 미커밋 구현은 기준 커밋만으로 식별하지 않는다.
2. 실제 기준 자료를 복제한 격리 DB에서 사용자 입력→검색/DB 조회→계산→저장·조회→실제 LLM 설명을 실행한다. 서비스 DB에 평가용 데이터를 쓰지 않는다.
3. API와 화면 포함 평가의 요청 경계를 명시한다. 현재 정식 입력 화면과 RAG는 미연결이며 실제 성능을 측정하려면 연결이 필요하다. 현재 에이전트의 근거 선택과 미구현인 물량 추출·추가 질문 생성을 혼동하지 않는다.
4. 요청별 검색 순위·답변·판정·실패 사유·응답 시간·usage를 기록한다. 개인정보·인증정보는 기록하지 않는다. 토큰·단가가 없으면 비용은 미측정으로 둔다.
5. 시간 집계에는 관측된 실패 요청 시간도 포함하고, 타임아웃 수와 제한 시간을 별도로 기록한다. 실패가 많은 버전의 짧은 응답 시간을 속도 향상으로 해석하지 않는다.
6. 지표별 단위·분자·분모·적용 사례 수·고유 사례 수·반복 수를 명시한다. 사람 평가와 자동 검사, 실제 LLM 평가와 Stub 검사를 구분한다.
7. 최초 실측값을 1차 Baseline으로 고정한다. 이후 같은 조건에서 재측정하고 차이와 악화도 기록한다. 조건이 다르거나 1차 버전을 재현할 수 없으면 직접 비교하거나 과거 값을 추정하지 않는다.

## 발표용 비교 표

| 지표 | 1차 개발 Baseline | 이후 개선 버전 |
|---|---|---|
| 전체 작업 성공률 / 공정표 정확도 | 실측 후 입력 | 이후 측정 |
| 질문별 정답률 / 근거 일치율 / 환각률 | 실측 후 입력 | 이후 측정 |
| Precision@5 / Recall@5 / MRR / nDCG@5 | 실측 후 입력 | 이후 측정 |
| P50 / P95 / P99 응답 시간 | 실측 후 입력 | 이후 측정 |
| 요청당 입력·출력 토큰 / 비용 | 실측 후 입력 | 이후 측정 |

현재는 지표 정의 완료, 실제 1차 성능 측정 대기 상태다. 기능·보안·회귀 테스트는 기본 검증으로 별도 수행하며 이 성능 수치와 구분한다.
